## Chapter 4: Deploying and Prompting Models in Microsoft Foundry — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Temperature parameter range and effect on AI responses? | 0.0 to 1.0. Lower (0.1) = deterministic, focused, consistent. Higher (0.9) = creative, varied, random. Exam tip: For factual/policy responses always use low temperature (≤0.3). Default is usually 0.7. |
| 2 | System prompt vs. User prompt — what's the difference? | System prompt: defines AI role, behavior, constraints—applies to ALL interactions. User prompt: specific query from end user—changes per request. Exam tip: Use system prompt for persistent rules (disclaimers, role limits), user prompt for the actual task. |
| 3 | Three main parameters in Chat playground that control response behavior? | 1) Temperature (randomness: 0=focused, 1=creative) 2) max_tokens (response length limit) 3) top_p (nucleus sampling: lower=fewer options). Exam tip: Temperature is most commonly tested for controlling consistency. |
| 4 | What does TPM stand for in Foundry deployment configuration? | Tokens Per Minute — the quota that limits endpoint throughput. Exam tip: TPM directly controls how many requests/minute based on token usage. Higher TPM = higher cost but better capacity. |
| 5 | GPT-4 vs GPT-3.5-turbo — when to choose which? | GPT-4: complex reasoning, longer context, more expensive, slower. GPT-3.5-turbo: faster, cheaper, shorter context, good for most tasks. Exam tip: Choose 3.5-turbo unless scenario requires complex reasoning or long documents—cost optimization matters. |
| 6 | Basic Foundry SDK client initialization code structure? | client = OpenAI(endpoint=url, credential=key) response = client.chat.completions.create(model="...", messages=[...]) print(response.choices[0].message.content) Exam tip: Know this flow—initialize client, create completion, access response.choices[0].message.content |
| 7 | What are Foundry Tools and when to use them? | Pre-built components for common tasks: summarization, extraction, Q&A. Use when task matches a tool (faster than custom prompting). Exam tip: If scenario mentions 'extract data' or 'summarize documents' → consider Foundry Tools first. |
| 8 | Three prompt engineering principles for effective prompts? | 1) Be specific (clear task, constraints, format) 2) Provide examples (few-shot learning) 3) Iterate and test. Exam tip: Specificity > vague instructions. 'Extract dates in YYYY-MM-DD format' beats 'find dates'. |
| 9 | Where in Foundry portal do you start deploying a model? | Models catalog → select model (GPT-4, GPT-3.5-turbo, SLM) → deployment wizard → configure name, quota (TPM), settings → deploy to endpoint. Exam tip: Catalog = browse models. Deployment = create usable endpoint. |
| 10 | What does max_tokens parameter control? | Maximum length of the AI response in tokens (~4 chars/token). Does NOT control input length. Exam tip: If response is cut off → increase max_tokens. If you want shorter answers → decrease it. Unrelated to randomness. |
| 11 | In SDK messages array, what are the valid role values? | "system" (defines AI behavior), "user" (end user message), "assistant" (AI previous response for multi-turn). Exam tip: System role = persistent instructions. User role = the actual query. Order matters: system first, then conversation. |
| 12 | Few-shot prompting — what is it and why use it? | Including examples in prompt to show desired behavior/format. Example: 'Extract names. Input: John went to Boston. Output: John'. Then give real task. Exam tip: Use few-shot when output format is critical or task is ambiguous—models learn from examples. |
