## Chapter 5: Building Chat Apps and Single-Agent Solutions — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What is the key difference between a chat application and an agent in Azure AI Foundry? | Chat applications respond to prompts. Agents make decisions and invoke tools autonomously. Exam tip: If the question mentions 'automatically invoke', 'decide when to call', or 'without explicit instructions' → agent. If just responding to user input → chat app. |
| 2 | Azure AI Foundry SDK: Three required steps to send a chat message? | 1) Initialize client with endpoint and key, 2) Build message array with system/user/assistant message objects, 3) Send request using client.complete() or equivalent. Exam tip: Message array structure is heavily tested — must include role and content for each message. |
| 3 | How do you maintain conversation context in Azure AI Foundry chat applications? | Include all prior messages (system, user, assistant) in the message array when sending each new request. The model receives full conversation history to understand references to earlier exchanges. Exam tip: Context ≠ streaming. Context = message array content. |
| 4 | What are streaming responses in Azure AI Foundry SDK and why use them? | Streaming receives tokens as they're generated instead of waiting for complete response. Better UX by showing immediate progress. SDK provides streaming methods that yield tokens incrementally. Exam tip: Streaming = UX improvement for response delivery, not context management. |
| 5 | What three elements are required in an Azure AI Foundry agent tool definition? | 1) Function name, 2) Parameters with types and descriptions, 3) Return types. Exam tip: Tool definitions enable autonomous invocation. Without proper definitions (especially parameter descriptions), agent can't decide when to invoke tools. |
| 6 | In Azure AI Foundry agents, what decides when to invoke which tool? | The underlying language model decides based on user query and tool definitions. Model reasons about which tools are needed. NOT keyword matching, NOT hard-coded sequences. Exam tip: 'Agent decision-making' = model autonomy, this is why it's an agent not a chat app. |
| 7 | Where do you observe tool invocations when testing an agent in Azure AI Foundry portal? | Foundry portal agent testing interface tool invocation logs. Shows which tools called, parameters passed, results returned. Exam tip: Portal testing interface is for development/debugging. Production monitoring uses Azure Monitor. |
| 8 | Azure AI Foundry SDK message array: What roles are valid for messages? | system, user, assistant. System = instructions/context, user = user input, assistant = model responses. Exam tip: Conversation history includes ALL roles. System message typically appears once at start, then alternating user/assistant. |
| 9 | Single-agent solution: When should you use it vs. chat application? | Use single-agent when solution needs to invoke tools autonomously (search, API calls, data retrieval, calculations). Use chat app when only responding to prompts without autonomous actions. Exam tip: Key word 'autonomously' or 'automatically decide' → agent. |
| 10 | What happens in Azure AI Foundry agent after it decides to invoke a tool? | Agent calls the tool with appropriate parameters, receives result, then incorporates result into response to user. Model may invoke multiple tools in sequence if needed. Exam tip: Tool invocation is transparent to user — they see final answer, not individual tool calls. |
| 11 | Azure AI Foundry SDK: What does client initialization require? | Endpoint URL and authentication key (or credential). Endpoint points to deployed Foundry resource. Exam tip: Endpoint and key are prerequisites for ANY SDK operations. Without valid initialization, no requests can be sent. |
| 12 | When configuring agent tools in Foundry portal, what makes a good parameter description? | Clear description of what parameter represents and when to use it. Model uses descriptions to decide tool invocation. Good: 'customer_id: unique identifier for customer account'. Bad: 'id: an id'. Exam tip: Parameter descriptions affect agent decision quality — they're not just documentation. |
