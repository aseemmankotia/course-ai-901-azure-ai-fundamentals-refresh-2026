## Chapter 7: Computer Vision and Image Generation in Foundry — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Image classification vs object detection: when to use each? | Image classification: assign ONE label to entire image (e.g., 'cat photo'). Object detection: locate MULTIPLE objects with bounding boxes + labels (e.g., '3 cats at coordinates X,Y'). Exam tip: Multiple objects + locations = detection. Single category = classification. |
| 2 | OCR accuracy: printed text vs handwritten text | Printed text: high accuracy (95%+). Handwritten text: lower accuracy, requires specialized models, varies by handwriting quality. Exam tip: Handwriting is supported but less reliable—plan for review workflows. |
| 3 | OCR table extraction limitation? | OCR supports table structure extraction BUT complex layouts (nested tables, merged cells, irregular spacing) may have errors. Exam tip: Simple tables = reliable. Complex tables = expect manual review needed. |
| 4 | Facial detection vs facial recognition vs facial identification | Detection: finds faces + attributes (age, emotion)—no identity. Recognition: 1:1 verification (compare 2 photos). Identification: 1:N search (find person in database). Exam tip: 1:1 = recognition, 1:N = identification. Both heavily regulated. |
| 5 | Facial recognition regulatory requirements? | Requires explicit consent, privacy compliance (GDPR, CCPA), data protection, limited retention. Facial identification (1:N) has stricter regulations, often restricted/banned. Exam tip: Identity verification = regulated technology, not general computer vision. |
| 6 | When is facial identification (1:N) typically restricted? | Heavily regulated for law enforcement, often requires legal authority, restricted in many jurisdictions (EU regulations, US state laws), demands strict data governance. Exam tip: 1:N search = highest regulation tier. Many real-world limits. |
| 7 | Text-to-image generation models in Foundry? | DALL-E and Stable Diffusion: create images from text prompts. Use case: generate product visualizations, marketing content, design mockups without photography. Exam tip: Text → Image = generation models. Image → Text = Computer Vision analysis. |
| 8 | Computer Vision API capabilities in Foundry? | Analyzes image content: generates tags, descriptions, detects brands, identifies objects. Does NOT generate images. Exam tip: Analysis (existing images) vs Generation (creating new images)—different services. |
| 9 | Computer Vision API brand detection: what it detects? | Identifies commercial brands/logos in images (e.g., Coca-Cola, Nike). Returns brand name + confidence score. Exam tip: Brand detection is separate capability from general object detection—optimized for logos/trademarks. |
| 10 | Vision model training data limitation? | Accuracy depends on training data diversity. Models may misinterpret cultural context, regional variations, underrepresented groups if training data lacks examples. Exam tip: Test with diverse datasets, expect cultural/contextual errors with non-Western content. |
| 11 | OCR form processing: what structured elements can it extract? | Checkboxes (marked/unmarked), form fields, tables, key-value pairs, layout structure. Combines with text extraction (printed + handwritten). Exam tip: Form/table extraction is built into modern OCR—not separate service. |
| 12 | Facial detection attributes returned? | Face location (bounding box), estimated age, emotion/expression, glasses/accessories, facial hair, head pose. Does NOT return identity. Exam tip: Attributes are estimates—not identity verification, no privacy/consent issues like recognition. |
